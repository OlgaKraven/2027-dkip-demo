# V18 · Текстиль для дома

Студия «Уют» выпускает продукцию «Декоративная подушка» по спецификациям. Магазин «Уют-1» заказал 30 ед. к 22.03.2027. Менеджер оформляет заказ, технолог задаёт состав, мастер планирует выпуск. Требуется связать документы в одной информационной системе и рассчитать нормативную стоимость заказа.

## Производственный процесс

Раскрой → пошив чехла → набивка.

## Правила учёта

Наполнитель учитывается по массе, молния — поштучно; норма ткани включает обе стороны чехла. Нормы заданы на одну единицу готовой продукции. Материалы: количество выпуска × норма × цена. Операции: количество выпуска × часы × тариф за час. Цены действуют с 01.03.2027, НДС, наценка, доставка и дополнительные накладные расходы не учитываются. Промежуточные суммы не округлять, итог округлить до копеек.

Авторский учебный вариант по структуре базового КИМ 09.02.07-5-2027. Не официальный экзаменационный вариант. 6 заданий, 210 минут, 75 баллов. Все организации и данные учебные.

Материалы и операции в спецификации различаются значениями material и operation. Время указано только для операций. Поле addres в JSON сохранено как имя входного поля. Пользователи manager, technologist и master — обычные пользователи, административную запись создайте отдельно. Пустой inn означает, что ИНН не предоставлен. Сохраните пустую строку; не придумывайте реквизиты. Идентификаторы id остаются текстом с ведущими нулями.

## Задание 1

По документам Студия «Уют» спроектируйте ER-диаграмму в 3НФ. Отразите заказчиков, продукцию «Декоративная подушка», спецификации с материалами и операциями, цены и производственный заказ. Для каждого документа определите реквизиты и повторяющиеся строки. Укажите PK, FK, кратности; сохраните PDF.

## Задание 2

Создайте базу для Студия «Уют» в выбранной СУБД по вашей схеме. Импортируйте все 6 записей из Заказчики.json. Сохраните ведущие нули кодов и пустые ИНН. Сопоставьте addres с полем адреса, а type с типом заказчика. Перенесите данные четырёх книг Excel: заказ покупателя V18-01, спецификацию, цены и заказ на производство V18-P01. Свяжите производственный заказ с заказом покупателя по номеру из файла. Проверьте внешние ключи, сделайте выгрузку и восстановите её в пустую базу.

## Задание 3

Создайте SQL-запрос нормативной стоимости заказа V18-01 предприятия Студия «Уют»: 30 ед. продукции «Декоративная подушка». Наполнитель учитывается по массе, молния — поштучно; норма ткани включает обе стороны чехла. Нормы заданы на одну единицу готовой продукции. Материалы: количество выпуска × норма × цена. Операции: количество выпуска × часы × тариф за час. Цены действуют с 01.03.2027, НДС, наценка, доставка и дополнительные накладные расходы не учитываются. Промежуточные суммы не округлять, итог округлить до копеек. Покажите материалы и операции отдельными строками и общую сумму.

## Задание 4

Создайте приложение Студия «Уют» на Windows Forms + MySQL либо WPF + PostgreSQL. Реализуйте вход по логину, паролю и пазлу, роли Администратор и Пользователь. Третья подряд ошибка пароля или пазла блокирует учётную запись. Администратор добавляет и изменяет пользователей, снимает блокировку. Создайте отдельного администратора и трёх обычных пользователей с логинами manager, technologist и master для задания 5. Проверьте пустые поля, дубли логинов и обработку ошибок. Для пазла возьмите файлы 1.png–4.png из приложения к заданию 4. В исходном изображении они идут слева направо, сначала верхний ряд, затем нижний.

## Задание 5

Реализуйте API заметок сотрудников Студия «Уют». Используйте users из задания 4. Создайте таблицу notes и свяжите notes.id_user с users.id. Загрузите 5 записей из Заметки.json. Для каждой записи найдите автора по login и перенесите created_date в created_at. GET /notes или GET /api/notes возвращает id, title_user в формате «title - login», content без изменений и formatted_date в формате ДД.ММ.ГГГГ. Поддержите необязательный параметр user_id, принимающий положительное целое число. Проверьте 200 с заметками, 200 и [] для пользователя без заметок, 400 для user_id=abc и 500 с JSON-сообщением при сбое подключения к тестовой базе. Сохраните коллекцию с исполняемыми проверками статусов и JSON.

## Задание 6

Документируйте API заметок Студия «Уют» в исходном шаблоне DOCX из приложения к заданию 6. Выполните запросы к своему ASP.NET Core Minimal API в Postman и возьмите фактические ответы из задания 5. Укажите базовый URL, реализованные методы и пути, тип и обязательность user_id, поля и типы ответа. Добавьте примеры 200 с заметками, 200 с пустым массивом, 400 и 500. Сверьте OpenAPI с реализацией и сохраните DOCX, OpenAPI JSON и тестовую коллекцию.

## Результаты

ER PDF, SQL и выгрузка БД, запрос стоимости, проект приложения, проект API и коллекция проверок, DOCX по шаблону, OpenAPI JSON. Приложения к заданиям 4–6 находятся в каталоге «Приложения» архива.
