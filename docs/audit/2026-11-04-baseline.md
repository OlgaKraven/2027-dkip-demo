# Аудит перед изменениями · 4 ноября 2026

Исходная версия: `9c6aa5bdbec84b1e942c385080d0eb3687d37325`.
Цель: самостоятельная подготовка студента, которому нужны явные первые действия, объяснения терминов, наблюдаемый результат и помощь при ошибке. Экспертный проход не является апробацией с реальными студентами.

## Что уже есть

КИМ 09.02.07-5-2027, ГИА БУ: шесть заданий, 210 минут, 75 баллов. Два маршрута: WinForms + MySQL/MariaDB и WPF + PostgreSQL. Для каждого — 72 шага; исходные документы, ER с происхождением полей, SQL, приложение, API, Postman и заполненный DOCX. Есть 30 авторских вариантов, презентация, тренировка и локальное сохранение. Исходная сборка и 11 тестов выполнены успешно на macOS.

## Границы проверки

Прочитаны исходники двух учебных маршрутов, управление состоянием, схема и общая логика C#, структура вариантов и существующие тесты. В браузере воспроизведены обучение, тренировка, начало и пауза, пробный экзамен. Снимок исходной паузы сохранён отдельно. Запуск Windows и живые проверки API выполняются отдельно; прежний `docs/QA.md` не засчитывается за текущую проверку. Все 30 самостоятельных решений студентов не реализованы и не проверены.

## Порядок переноса на другие курсы

1. Закрепить SHA, год, квалификацию, базовый комплект, время и баллы; прочитать инструкции целевого репозитория.
2. Пройти каждый этап буквально без скрытых знаний: исходное состояние → действие → видимый результат → ошибка и восстановление.
3. Отдельно проверить готовые примеры в настоящей целевой среде на изолированных базах.
4. Воспроизвести начало, паузу, перезагрузку, истечение времени, завершение, протокол и повтор; проверить изоляцию вариантов, режимов и СУБД.
5. Проверить узкое, среднее и широкое окно, две темы, клавиатуру, модальные окна, ER и презентацию.
6. Исправлять общий компонент и источник содержания; переносить решение по смыслу. API, модули, длительность и баллы одного КИМ не копировать в другой.
7. Повторить отрицательные проверки найденных ошибок, затем сборку и публикацию. Различать готовый код, понятное обучение, локальную проверку и опубликованный результат.


## Уточнения после исходного аудита

- Пользователь подтвердил: заметный экран паузы нужен только в тренировке; пробный экзамен остаётся непрерывным.
- После завершения нужна новая попытка по повторному нажатию. Предыдущий протокол сохраняется отдельно.
- По двум скриншотам пользователь расширил удаление личных заметок на тренировку и потребовал убрать весь нижний футер. Это не касается учебной таблицы/API notes.
- Для новых Windows-снимков разрешён `prlctl capture`. Инструмент управления нативным окном зависает; отрисовка некоторых кадров содержит чёрные области. Такие кадры не принимаются как учебные иллюстрации.


Дополнительная визуальная проверка: исходная синяя ссылка `#4561c8` на тёмном фоне `#22252a` даёт контраст 2,78:1; белая подпись на исходной красной кнопке `#ed1737` — 4,39:1. Для читаемости нужны отдельный светлый цвет ссылок в тёмной теме и немного более тёмная заливка красных кнопок. Университетская палитра и маскот сохраняются.


## A12 · Реальное окно WinForms при масштабе Windows 200%

При текущем запуске в VM исходная форма открылась примерно 550 × 640 физических пикселей: заголовок переносился внутри слова, пазл и кнопка входа находились за нижней границей видимой области. Это реальный дефект окна, которого не выявили сборка и 15 проверок общей логики. Добавить явное DPI-масштабирование программно создаваемых WinForms-форм и повторить запуск. Исходный кадр сохранён как доказательство; не использовать его как изображение готового решения.


## A13 · Пазл и исходные приложения

Просмотрены все четыре PNG приложения 4. Это четыре квадранта одной картинки, а исходный код обоих маршрутов повторно разрезал только `1.png`, то есть один квадрант. Кроме того, WinForms показывал маленькие фрагменты без растяжения при DPI 200%. Исправление: использовать все четыре исходных PNG без изменения файлов, собирать из них образец и переставлять эти же части; поддержать размер кнопок. Повторить проверку и заменить изображения входа/пазла, где старое состояние могло вводить студента в заблуждение.


## A14 · Подключение и последовательность для начинающего

Исходная библиотека Shared использует оба провайдера. Её Database.cs нельзя без адаптации переносить в проект, куда установлен только один NuGet-пакет. Для собственного проекта добавлены отдельные однопровайдерные Database.cs в starter; пространства имён нужно согласовать с MyApp. Подготовительные действия встроены в точку использования, исключён повторный CREATE/INSERT после вводного блока. Основной маршрут — окна Visual Studio, СУБД и Postman; команды сопровождения сохранены отдельно в docs/development. Инструкции и презентация используют одну последовательность.
