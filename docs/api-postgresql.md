# Документация API заметок

Базовый URL: http://127.0.0.1:5272. Маршрут: postgresql. Сервер локальный; он запускается на компьютере читателя.

## GET /notes

user_id: необязательное целое > 0, query. Пример: ?user_id=2. Без параметра — все заметки. Повтор и неизвестные параметры дают 400.

Возвращает список заметок из notes и логин автора из users. Запрос: GET http://127.0.0.1:5272/notes. Фильтр: GET http://127.0.0.1:5272/notes?user_id=2.

JSON, массив объектов. id — код заметки; title_user — title + « - » + login; content — исходное содержание без изменений; formatted_date — дата в формате ДД.ММ.ГГГГ.
Пример одного элемента ответа (полный список содержит 5 записей):
[{"id":1,"title_user":"Заметка 1 - student","content":"Содержание заметки 1","formatted_date":"15.03.2027"}]

## GET /api/notes

user_id: необязательное целое > 0, query. Пример: ?user_id=2. Без параметра — все заметки. Повтор и неизвестные параметры дают 400.

Псевдоним GET /notes. Запрос: GET /api/notes?user_id=2. Правила и поля ответа совпадают.

Тот же JSON-массив заметок. Пустой результат: [] при user_id=2147483647.

## Коды ответов HTTP

200 — Успех. Content-Type: application/json. Массив заметок; если подходящих записей нет — []. Пример: GET http://127.0.0.1:5272/notes?user_id=2147483647 → 200, [].

400 — Ошибка параметра. Пример: GET http://127.0.0.1:5272/notes?user_id=abc → 400, {"error":"user_id должен быть положительным целым числом"}.

500 — Сбой БД или обработки. Ответ: {"error":"Ошибка подключения к базе данных или обработки запроса"}. Проверка: отдельный экземпляр API с неверным портом БД 1 на http://127.0.0.1:5282/notes. Рабочая БД не останавливается.

Swagger UI: http://127.0.0.1:5272/swagger/
OpenAPI JSON: http://127.0.0.1:5272/openapi.json

Служебные адреса показывают документацию; данные заметок возвращают два GET-метода выше. Коллекция: postman-postgresql.json.
