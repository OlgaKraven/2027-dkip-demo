0. Установка и настройка программ

  1. Скачайте установщик Visual Studio Community. Выберите «Разработка классических приложений .NET» и «ASP.NET и разработка веб-приложений». Для Windows Forms, WPF и API из ZIP нужны Visual Studio 2026 и .NET 10 SDK для Windows x64. Проверьте dotnet --list-sdks в PowerShell.
  2. Для маршрута Windows Forms скачайте XAMPP. Оставьте MySQL, Apache и phpMyAdmin. В XAMPP Control Panel запустите MySQL и Apache. Проверьте вход в http://localhost/phpmyadmin.
  3. Для WPF скачайте PostgreSQL с pgAdmin для Windows. Выберите сервер, pgAdmin 4 и Command Line Tools. Запишите пароль postgres и порт, обычно 5432. Откройте в pgAdmin ветку Databases.
  4. Установите diagrams.net Desktop (Windows installer), проверьте экспорт ER в PDF. Для API скачайте Postman для Windows x64 и проверьте импорт локальной коллекции. Если Postman требует вход в аккаунт, для домашней офлайн-проверки используйте Invoke-RestMethod.
  5. Проверьте, что открываются DOCX, XLSX, PDF и RAR. Если не хватает программ, скачайте LibreOffice или 7-Zip для Windows x64.

Библиотеки и разработка без интернета

Подключите пакеты в новом проекте

Заранее скачайте набор NuGet-пакетов для MySQL или для PostgreSQL. Поместите nuget-packages и NuGet.Config в папку своего решения. Отдельные драйверы можно скачать по ссылкам MySqlConnector 2.6.1 и Npgsql 10.0.1. Оставьте файлы .nupkg целыми и используйте зависимости из набора.

В Visual Studio выберите проект с кодом БД → «Управление пакетами NuGet» → «Обзор» → источник «Пакеты из архива». Установите драйвер выбранной СУБД и соберите решение без сети. При NU1101 или NU1102 сверьте имя и версию отсутствующего пакета с содержимым папки.

В PowerShell из папки своего решения выполните команды ниже. Первая использует только локальный NuGet-источник, вторая собирает проект с уже восстановленными пакетами.

dotnet restore --configfile NuGet.Config --no-http-cache
dotnet build --no-restore

В обозревателе решений Visual Studio назначьте стартовым свой оконный проект или Api. Для API заполните переменные подключения в профиле отладки, как показано в карточке. Запустите F5 и проверьте созданную базу.

Если на стенде .NET 9

.NET 10 — LTS. .NET 9 завершил поддержку 10 ноября 2026 года. Для стенда с .NET 9 используйте .NET 9 SDK и Visual Studio 2022 17.12 или новее. Для .slnx используйте VS 2022 17.14 и SDK 9.0.2xx или новее.

В отдельной копии в .csproj настольного проекта замените net10.0-windows на net9.0-windows. В проектах Shared, Api, Tools и импортёре замените net10.0 на net9.0. Версии драйверов сохраняются. Для Npgsql под .NET 9 нужны Microsoft.Extensions.Logging.Abstractions и Microsoft.Extensions.DependencyInjection.Abstractions версии 9.0.0. Оба пакета входят в набор для PostgreSQL. Повторите dotnet restore и dotnet build, затем выполните F5 с прежними настройками СУБД.

ЧаВО об экзамене

Какие задания на базовом уровне?

КИМ 09.02.07-5-2027 отводит 210 минут на шесть заданий. В курсе разбираются ER, база и импорт, расчёт стоимости, формы и роли, API и его документация.

Будет ли доступ к сайтам и пакетам?

На с. 22 КИМ указана локальная сеть без доступа в интернет. Для домашней репетиции заранее установите ПО и подготовьте пакеты, затем проверьте всё без внешней сети. Список разрешённых программ, файлов и локальной справки уточните на инструктаже.

Что уточнить перед началом?

Сверьте версии .NET, доступную СУБД, путь к исходным файлам, папку сдачи и допустимый способ проверки API. Если комплект или рабочее место не открываются, сообщите эксперту номер места и текст ошибки.

Что проверить перед сдачей?

Откройте PDF, проверьте SQL и данные в отдельной базе, запустите приложение под обеими ролями. Проверьте ответы API и сохраните проект с документацией в папке сдачи.
