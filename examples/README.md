# Учебные примеры: запуск в Visual Studio

Windows 10/11, Visual Studio с компонентами «Разработка классических приложений .NET» и «ASP.NET и веб-приложения», .NET 10. Сайт показывает обучение; файлы и базу создают на своём компьютере.

## Подготовьте отдельную базу

1. Распакуйте архив через Проводник → правой кнопкой по ZIP → «Извлечь всё».
2. Откройте извлечённую папку. Внутри должны быть `examples`, `docs`, `materials`.
3. MySQL: XAMPP → Start у MySQL и Apache → Admin у MySQL → phpMyAdmin → «Создать БД». PostgreSQL: pgAdmin → ваш сервер → правой кнопкой по Databases → Create → Database.
4. Создайте **новую пустую** базу `dkip2027_course`. Для MySQL выберите utf8mb4.
5. Выберите эту базу. В phpMyAdmin откройте «Импорт» и укажите `examples/mysql/Sql/01-schema.sql`. В pgAdmin откройте Query Tool → Open File → `examples/postgresql/Sql/01-schema.sql` → Execute.
6. Обновите список таблиц. Должны появиться таблицы схемы.

## Загрузите данные готового примера

1. Откройте Visual Studio → «Файл» → «Открыть» → «Проект или решение».
2. Выберите `examples/Tools/Dkip.Tools.csproj` из распакованной папки.
3. Дождитесь загрузки зависимостей. Выделите проект в Обозревателе решений.
4. Выберите меню «Отладка» → «Свойства отладки Dkip.Tools». Другой путь: свойства проекта → «Отладка» → «Открыть профили запуска отладки».
5. В таблице Environment variables добавьте `DKIP_STACK` со значением `mysql` или `postgresql`.
6. Добавьте `DKIP_CONNECTION`. Для MySQL основа: `Server=127.0.0.1;Port=3306;Database=dkip2027_course;User ID=root;Password=;Character Set=utf8mb4`. Для PostgreSQL: `Host=127.0.0.1;Port=5432;Database=dkip2027_course;Username=postgres;Password=ВАШ_ПАРОЛЬ`. Замените параметры своей учебной установки. Пароль сервера БД сообщает преподаватель или задаёт ваша установка.
7. В поле «Аргументы командной строки» введите `seed`, затем пробел и полный путь к `materials/basic/Задание 1/Заказчики.json` в двойных кавычках. Слово seed — аргумент программы, никаких команд выполнять не требуется.
8. Сохраните профиль. Нажмите «Отладка» → «Запуск без отладки» (Ctrl+F5).
9. После сообщения о загрузке вернитесь в редактор БД и проверьте таблицы. Если запуск прервался, повторите его с теми же настройками и файлом в этой учебной базе. Утилита добавит недостающие записи и сохранит существующие.
10. Для проверки замените аргументы запуска на `check` и повторите Ctrl+F5. Для интеграционных проверок на отдельной тестовой базе используется аргумент `test`; он создаёт и изменяет тестовые записи, не запускайте его на рабочей базе.

Свойства запуска сохраняются локально в `Properties/launchSettings.json`. Файл с настоящим паролем не отправляйте в Git.

## Откройте приложение

1. В Visual Studio откройте `examples/mysql/Dkip.WinForms.csproj` либо `examples/postgresql/Dkip.Wpf.csproj`.
2. Через свойства отладки задайте этому проекту те же переменные подключения. Настройки другого проекта автоматически не переносятся.
3. Нажмите Ctrl+F5. Должно открыться окно входа.
4. Введите учебную запись `admin / Demo2027!` или `student / Demo2027!`. Это пароли приложения, а не сервера БД.
5. Слева показан образец изображения, справа четыре фрагмента. Нажмите два фрагмента, чтобы поменять их местами. Повторяйте до совпадения с образцом.
6. Нажмите «Войти». После подтверждения откроется рабочее окно с логином и ролью.
7. У администратора доступен список пользователей. Выберите строку, измените данные и сохраните. Третья подряд ошибка пароля или пазла блокирует запись; блокировка сохраняется после перезапуска.

## Откройте API и Postman

1. В другом окне Visual Studio откройте `examples/Api/Dkip.Api.csproj`.
2. В свойствах отладки выберите профиль запуска проекта http, задайте DKIP_STACK и DKIP_CONNECTION.
3. В App URL задайте `http://127.0.0.1:5271` для MySQL или `http://127.0.0.1:5272` для PostgreSQL.
4. Сохраните профиль, выберите его рядом с зелёной кнопкой запуска и нажмите Ctrl+F5.
5. В браузере откройте этот адрес с `/notes`. Должен появиться настоящий JSON из выбранной базы.
6. В Postman отправьте GET /notes. Сверьте статус 200 и JSON во вкладке Body.
7. В Postman нажмите Import → выберите `docs/postman-mysql.json` или `docs/postman-postgresql.json` → Import. Отправьте запросы коллекции.
8. Для 500 используйте отдельную копию проекта и отдельный профиль DkipError. В его DKIP_CONNECTION задайте неработающий порт БД 1 с коротким таймаутом; App URL — порт API 5281 или 5282 соответственно. Запустите эту копию и проверьте запрос error_url в Postman. Основную СУБД и её параметры не меняйте.
9. После проверки завершите только тестовую копию. Подробности исключения остаются у сервера; клиент получает JSON error.

Этот пример предназначен для сверки. В обучении студент создаёт собственный проект по микрошагам; в пробном экзамене используются данные выбранного авторского варианта.
